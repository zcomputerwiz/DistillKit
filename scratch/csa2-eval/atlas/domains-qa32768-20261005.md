# Frozen QA extension, CPU preparation only

The atlas's additional 16,384-token prefix cap removed most answer turns from its
fixed QA sample. The new `domains-qa32768-20261005.pt` keeps the same seed-0 sample
and raises only QA's cap to 32,768. All 16 selected cached documents fit completely:
their longest stored document has 31,521 tokens.

| Documents | 16 | 16 |

Own-turn targets use the existing assistant/thinking/tool-call role labels, shifted to
the next-token target positions. The new 8,773 include 696 assistant-formatting newline
tokens in addition to 8,077 answer-body tokens. QA remains mostly user context even
after the extension; the own-turn ledger is necessary to assess answer behavior.

The source-cache audit reproduced the picked IDs independently from cache and JSONL
metadata without Torch/GPU imports. QA2 contains all 841 verified source documents,
with no capture-stage clipping (`length == original_length` in every cache record);
the maximum stored length across the full cache is 32,735. The upstream QA input
builder stops before the first oversized complete question-answer trial
(`scratch/frontier/capture_inputs.py:85-87`). It omitted 12 later questions before
capture: eleven in `flash-attention:21`, and one in `rich:8`. Raising the atlas cap
cannot recover those questions. The current selected 16 documents do not appear in
the seven-document literal-chat-markup flag list, so that known role-scanner caveat
does not affect this sample.

The builder verifies every original token prefix and role prefix in all eleven domains
before writing. All ten non-QA domains are exactly unchanged. The llama.cpp source
documents were reused from the original artifact rather than read from the live tree.

The domains CLI masks CUDA before importing Torch, mocks CUDA availability and rejects

confirmed that extension mode refuses to overwrite original `domains.pt`. No model
execution, GPU evaluation, training recipe change or model-code change occurred.
